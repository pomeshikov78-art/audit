# Регрессионные автотесты интерактивной модели аудита НИОКР

Набор harness-файлов (Node.js + jsdom) для автоматической проверки модели
`output/Аудит_НИОКР_интерактивная_модель.html` и её версий.

## Требования

- Node.js ≥ 16;
- jsdom: `npm install jsdom` (в любой директории, откуда запускаете тесты).

## Запуск

```bash
# из корня репозитория/пакета
node scripts/tests/test_v18.js     # 60 проверок: ТРЁХУРОВНЕВАЯ СИСТЕМА 15/30/60 (v18.0) — ТЕКУЩИЙ БАЗОВЫЙ КОМПЛЕКТ
node scripts/tests/smoke18.js      # 107: движок этапа 18 (Q18, calc18, econ18, ahp18cr, stops18, миграции)
node scripts/tests/ui18.js         # 42: UI опросника (уровни, якоря, Ф-06, NPV/BCR, AHP-переключатель)
node scripts/tests/import18.js     # 76: импорт книги «9_Калькулятор_аудита_НИОКР_v2.xlsx» в модель
node scripts/tests/probe18b.js     # 30 клик-сценариев jsdom (PART B: деки, акты, MC/торнадо, сценарии, персоны)
# исторические комплекты (структуры 27/31 вопросов / версионные строки — на v18.0 не проходят):
node scripts/tests/test_v17.js     # 147: выгрузка чек-листа в Markdown (v17.0)
node scripts/tests/test_v16.js     # 131 проверка: портфельная матрица «I_А × I_Ц» (v16.0)
node scripts/tests/test_v15.js     # 112 проверок: экспертная методика А/Ц, структура 31, миграция 27→31 (v15.0)
node scripts/tests/test_v14.js     # 54 проверки: отчётность, портфельный дек (v14.0)
node scripts/tests/test_v13.js     # 54 проверки: графический дашборд (v13.0)
node scripts/tests/test_v12.js     # 74 проверки: предложения (v12.0)
node scripts/tests/test_v11.js     # 69 проверок: база НИОКР и история аудитов (v11.0)
node scripts/tests/test_v10.js     # 71 проверка: респонденты (v10.0)
node scripts/tests/reg_v9.js "путь/к/файлу.html"   # 22 якоря v1–v9 (расчёт, AHP, вкладки)
node scripts/tests/test_v9.js      # исторический harness v9 (якоря дублирует reg_v9)
```

Важно: `test_v10…v17` и `reg_v9.js` (по умолчанию) обращаются к рабочему файлу по
абсолютному пути workspace, зашитому в первых строках каждого файла — при переносе
на другую машину замените константу `P` на свой путь. `reg_v9.js` принимает путь к
HTML первым аргументом командной строки.

**Этап 18 (v18.0) — breaking change:** модель переведена на систему 15/30/60 (спецификация «Научно.docx»): r.q = {K:{код→{a,j,e}}, S:{А1…В10}, P:{…60}}, плюс v18extra{budget,trl,imp}, ahp18, m09; легаси-массивы r.ans/conf/com ушли в `legacy31` (миграции 27→31→30 через `Q18.mig31`/`LEG2S31`). Базовый комплект — `test_v18.js`; `test_v9…v17` сохранены исторически. Ключевые потребители перенесены в этапе 18Б (см. `scripts/patch18_consumers_b.py` и журнал VERSIONS п. 24): respStats (контракт n/rows/cI/mode/dis по qS), setQA18 (маршрутизация в активную персону + syncConsensus), discrepancies (коды + v18extra + flagsOn), scChip/avgScore/qList (LEG-обёртки), fixAuditModal (восстановление q/qS/легаси), Монте-Карло и торнадо (idxFake18 по кодам, полосы 85/70/55), сценарии (снимок qS + `scenTargets`), renderEvid (фильтры направлений, gotoQ по позициям кодовой сетки), propModal (цели по кодам), buildSlides (слайд 4 — экономика NPV/BCR/LCC; слайд 9 — таблица направлений с Coverage; устранён крах чтения `c.bl`), expertDashCard (PLVLC), KB (expKBHTML целиком, якоря 30 кодов из `Q18.levels.S.q[].anch`), TOUR 6 шагов, «чек-лист→опросник» со защитой исторических сносок; `window.niokrAPI` расширён до 137 функций (calc, ansS30, CODES30, scenTargets, iAtWeights).

**Этап 17 (v17.0):** новых полей данных нет — выгрузка чек-листа в Markdown производна от calc(r) и существующих полей (ans/conf/com/stops/flags/prospect/decision и др.); test_v17 = test_v16 с обновлёнными версионными строками + 16 проверок MD-экспорта (структура документа, 31 строка вопросов, P₁/P₂/P₃ = 80.0/62.2/76.7, «НП» → «Н/П», I/I_А/I_Ц с уровнями, 5 позиций заключения, стоп-факторы, скачивание «Чек-лист_НИОКР_НИОКР-01_31.md», niokrAPI, приветствие). Скачивание проверяется заглушкой `HTMLAnchorElement.prototype.click` (jsdom не умеет download-ссылки).

**Этап 16 (v16.0):** новых полей данных нет — матрица на «Графиках БД» производна от calc(r).iA/iC и stopsOn(r); test_v16 = test_v15 с обновлёнными версионными строками + 19 проверок матрицы (recGroup, 25 ячеек, точки/стоп-кольца, клик, printViz, фильтры, niokrAPI). Клик по SVG-`<g>` в jsdom — только dispatchEvent(new MouseEvent("click",{bubbles:true})).

**Этап 15 (v15.0) — breaking change:** блоки I и III чек-листа заменены экспертной
методикой «Актуальность + Целесообразность» (31 вопрос вместо 27). Комплекты
`test_v9…test_v14` и `reg_v9` написаны под структуру 27 вопросов и сохранены как
исторические: для прогона на v15.0 они требуют переразметки якорей (стартовый
массив A длиной 31, новые индексы вопросов, новые ожидаемые значения). Актуальный
базовый комплект — `test_v15.js`; он покрывает и сквозные механизмы v9–v14
(респонденты, предложения, БД, слайды, отчёты) на новой структуре данных.
Для проверки версий v1.0…v14.0 используйте соответствующие harness-файлы вместе с
файлами из `output/versions/`.

## История

Harness-файлы обновлялись на каждом этапе (v10 → v15 вкладок и т. д.); после каждого
прогона все файлы копируются в эту папку, чтобы пережить очистку /tmp.
