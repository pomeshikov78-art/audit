## 1. Ядро данных и расчёта (заменяет QS/NQ/calcCore/dirIdx/expertRec)
- Q18 = данные из q18.json (инлайнятся в HTML как const Q18={...}).
- Состояние НИОКР (r): r.lvl ('K'|'S'|'P', default 'S'); r.q = {K:{},S:{},P:{}} — словари по коду вопроса:
  {a:''|'0'..'5'|'НД'|'НП', j:обоснование, e:доказательство}. Ответ ОДИН (консенсус), как r.ans в v17.
- r.sf=[5] ('' | 'ДА') — проверки SF-2; r.mat={cur:0..9|null, plan:0..9|null, tests:'Да'|'Нет'};
  r.econ={rate:0.1, T:5, lcc:[8 чисел], flows:[[Bt,Ct]×(T+1)], alt:{c:[9],d:[9],e:[9],f:[9]} (0–5), altW:[9]};
  r.ahp18={dir:3×3, A:4×4, Б:4×4, В:4×4 (значения 1..9, верхний треугольник), useBlocks:bool};
  r.legacy31={ans,conf,com,stops,flags} — архив v17 (не редактируется); r.prospect сохраняется.
- Движок idx18(r, lvl):
  * K/S: по направлению d: R=Σw(числовые), Ssum=Σw·x, T=Σw(не «НП») → I_d=ROUND(Ssum/(5R)·100,1) или null;
    Coverage=ΣR/ΣT·100 (K: w=1; S: w из q18; «НД» — в T, не в R; «НП» — вне обоих).
  * P: Dk блока=среднее вопросов блока ×20 (Σx/(5·n_числ)), I_d=Σ(E_blk·Dk)/ΣE_blk применимых;
    E_blk = ahp18-веса (useBlocks и CR≤0.10) или базовые (А .2/.2/.2/.4; Б .25×4; В .3/.25/.3/.15);
    Coverage P = по ВОПРОСАМ (w=1, как в Excel).
  * kompl=∛(IA·IC·IR); min; counters: flags (вопросы «к обсуждению»: 4–5 без доказательства / 0–2 без обоснования),
    ctrl (НП без j), low2 (x≤2).
- Заключение concl18(r,lvl) — ЗЕРКАЛИТ формулы Excel № 9 (порядок ветвей 1:1):
  K: min=null→«Недостаточно данных…»; SF2>0→эскалация; Cov<80→«Оценка предварительная…»; ≥80/≥60/≥40/иначе — 4 формулировки CONC15;
  S: null→…; SF2→«IV. Отрицательное / эскалация…»; Cov<85→«Недостаточно данных… (Coverage ниже порога 85%)»; min≥85→«I. Положительное…»; ≥70→«II. Положительное с замечаниями…»; ≥55→«III. Отрицательное с возможностью корректировки…»; иначе «IV.» (тексты CAT30/Excel);
  P: null→…; SF2→R7; Cov<90→…; все<55→R7; все≥85→R1; min≥70→R2; альтернатива≠«Продолжить разработку»→R6; Б3<70→R5; IA<70∧IC≥70→R4; IC<70∨IR<70→R3; иначе R2.
- Общие правила (Заключение 47–50): Coverage<порог; IA<55; IC<55; IR<55 → записи.
- autoRecs18(r): 15 правил AUTO_REC по кодам S-уровня (считаются по r.q.S независимо от активного lvl — как в Excel); + low2-счётчики активного уровня.
- AHP18: веса=нормированные ∏^(1/n); λmax=Σ((Mw)_i/(n·w_i)); CI=(λmax−n)/(n−1); CR=CI/RI[n] (ri из q18); проверки ✔/✘ ≤0.10; crMax по 4 матрицам.
- Экономика18: PV потоков по rate/T; NPV=Σ(B−C)/(1+r)^t; BCR=PV(B)/PV(C) + текст BCR-таблицы; LCC=Σ lcc (PV);
  альтернативы: Us=Σ(w·x) по 9 критериям ×4 сценария (имена: «Продолжить разработку» + ALTNAMES[1..3]); best=argmax; margin=best−Us(продолжить).
- Зрелость18: dev=cur−plan; note (опережение/соответствует/отставание); warn: cur≥5 ∧ tests≠'Да' → «⚠ M{cur} заявлена без подтверждения испытаниями…».
- Стоп18: n2=Σ(sf=='ДА'); res: 0→'SF-0: обычный порядок оценки'; SF-1 правила (q18.sf2 — все пять = проверки SF-2; «SF-1» в модели = предупреждения уровня «признаки» — в Excel B-колонка одна; зеркалим Excel: только SF-2 статусы) → n2>0: 'SF-2 …эскалация…безусловно положительное заключение невозможно'.
- calc(r) — КОМПАТ-ОБЁРТКА для потребителей v5–v17: c.I=kompl активного lvl (null→null); c.cat=уровень по POROG_LVL (85/70/55: Высокий/Приемлемый/Проблемный/Критический); c.rec=concl18; c.bl=[{P:IA/100},{P:IC/100},{P:IR/100}] (3 «блока»=направления); c.renorm=false; iA/iC → IA/IC активного lvl; +c.iR,c.cov,c.min,c.conc,c.recs,c.sf2,c.mat,c.econ. Старые expertRec/RECMX/lvl5/LVL5N/STOPS/FLAGS/FLAGBAD/CRIT_A/BRNG → удаляются или заменяются (внимание: LVL5N используется матрицей v16 — матрица «I_А × I_Ц» ПЕРЕОПРЕДЕЛЯЕТСЯ на новую сетку порогов (85/70/55) 4×4 с рекомендациями POROG_LVL/CONC-логики; recGroup остаётся).

## 2. UI
- Вкладка «Чек-лист» → «Опросник»: селектор уровня (Краткий/Средний/Полный) + карточка цели уровня; секции по направлениям (А/Б/В) с заголовками; строка вопроса: код, текст, подсказка (K: якоря 5/3/0; S: check+ev(+anch); P: est+ev+блок), селект 0–5/НД/НП, поле обоснования j (НП без j → контрольное замечание + popup как в v17), поле доказательства e (для 4–5 обязательно → флаг), вес (S), бейдж low2.
- Сводка уровня: I_А/I_Ц/I_Р + уровни (85/70/55), комплексный, Coverage + порог ✔/✘, счётчики (к обсуждению/замечания/≤2), ЗАКЛЮЧЕНИЕ (уникальное для уровня), авторекомендации (сработавшие), кнопки: «Экспертное заключение» (генератор Ф-06 по TMPL из данных активного уровня), «Чек-лист (MD)» (новая структура).
- Вкладка «Эксперты/Стоп» → стоп-факторы (5 проверок SF-2, статус ДА/нет, блокирующая плашка), зрелость M0–M9 (cur/plan/tests → note/warn), точки повторной проверки CKPT, ранние сигналы EARLY (сравнение с последним снимком r.audits: падение индекса ≥10, Coverage<85, SF-2).
- Вкладка «AHP» — переопределить: 4 матрицы (направления 3×3 + блоки А/Б/В 4×4), шкала Сати 1–9, веса, λmax/CI/CR/RI, crMax, переключатель «Использовать веса AHP в полном опроснике».
- Вкладка «Экономика» (новая или в «Финансы»): ставка/горизонт, LCC 8 стадий, потоки Bt/Ct, NPV/BCR+текст, альтернативы 4×9 (веса критериев, оценки 0–5, Us, best, margin).
- Дашборд/KPI: I=комплексный, три направления вместо блоков, Coverage-бейдж, заключение уровня; панель руководителя (early warning + счётчики) — по образцу Excel «Панель_руководителя».
- Кнопка «⬆ Импорт Excel № 9» (в шапке и на вкладке опросника): input[type=file] → xlsx18.read(ArrayBuffer) → модальное окно предпросмотра (найденные листы, число заполненных ответов по уровням, паспорт, SF, M, экономика) → «Применить» → запись в r (lvl из Паспорт!C17; ответы M/N/O по строкам; H/I/J игнорируются — M итоговый) + notify + запись в журнал.
