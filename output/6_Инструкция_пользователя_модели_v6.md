# ИНСТРУКЦИЯ ПОЛЬЗОВАТЕЛЯ

## Интерактивная модель аудита НИОКР, v6.0

Файл: `Аудит_НИОКР_интерактивная_модель.html` (единый автономный файл; история версий — `versions/Аудит_НИОКР_модель_v1.0…v6.0.html`, журнал — `VERSIONS.md`).

**Назначение:** проведение аудита актуальности, эффективности и целесообразности НИОКР по финальному чек-листу v2.0 (27 вопросов, 3 блока с базовыми весами 30/35/35 и возможностью их обоснованной настройки методом AHP) с автоматическим расчётом интегрального показателя I (0–100), обработкой ответов «Н/П», **реестром доказательств с показателями доказательной зрелости D и соблюдения правила 4–5 K**, аналитикой устойчивости решения и формированием акта оценки.

**Требования:** любой современный браузер (Chrome, Edge, Firefox, Safari). Интернет не нужен: все стили, скрипты, изображения и база знаний встроены в файл. Данные хранятся локально в браузере (localStorage) и никуда не передаются.

---

## 1. Быстрый старт

1. Откройте файл двойным кликом.
2. При первом запуске появится приветственное окно — «Начать работу» (или «🧭 Тур» в верхней панели — 9 шагов).
3. Выберите НИОКР в селекторе верхней панели или добавьте новую кнопкой «＋ НИОКР».
4. Заполните чек-лист (вкладка «✅ Чек-лист»): ответ, документальное подтверждение, комментарий. Кнопка **📎 у каждого вопроса** открывает его документы в реестре доказательств.
5. Результаты — на вкладке «📊 Дашборд»; доказательная база — на вкладке «📎 Доказательства»; акт — «🖨 Акт оценки».
6. Если комиссия использует нестандартную схему весов — настройте её на вкладке «⚖️ Веса (AHP)» до формирования акта.

## 3. Вкладки

**📊 Дашборд.** I и категория; gauge-диаграмма; радар блоков; бары Pⱼ и Bⱼ; тепловая карта 27 ответов; контрольные условия; лента уведомлений. Под значением I — активная схема весов; при нестандартных весах — также I при базовой схеме 30/35/35.

**✅ Чек-лист (27).** Ответ, подтверждение, комментарий по каждому вопросу; итоги блока Sⱼ/Nⱼ/Pⱼ/Bⱼ. У каждого вопроса — кнопка **📎 со счётчиком документов** и красным **⚠**, если балл 4–5 не подтверждён предоставленным документом. Правила: 4–5 без подтверждения → popup (снизить балл / отметить подтверждённым при наличии документа в реестре / зафиксировать риск); «Н/П» → popup обоснования.

**📎 Доказательства** — нововведение v6.0:
- **KPI**: доказательная зрелость **D** (доля оценённых вопросов с предоставленными документами), соблюдение правила **«4–5 только с документом» K**, число документов по статусам, счётчик нарушений (дублируется бейджем ⚠N на кнопке вкладки);
- **разрез по блокам**: D и K по каждому из трёх блоков;
- **карта нарушений**: вопросы с баллами 4–5 без предоставленных документов и кнопка «→ к вопросу» (переход в чек-лист с подсветкой);
- **реестр**: наименование и реквизиты, тип (15 вариантов: ТЗ, договор, отчёт, протокол испытаний, акт приёмки/внедрения, РКД, патент/РИД, финансовый документ и др.), дата, статус (**Предоставлен / Заявлен / Запрошен / Отсутствует**), примечание; фильтры по блоку/типу/статусу и полнотекстовый поиск; добавление документов к любому вопросу или «общих» (вся НИОКР); удаление с подтверждением;
- **экспорт CSV** и **печать реестра** (акт-форма с D, K, нарушениями и подписями).

Ключевая автоматизация: статус «Предоставлен» **автоматически устанавливает подтверждение «Да»** по вопросу (с уведомлением) и снимает ⚠-флаг; обратное действие — вручную в чек-листе.

**📈 Аналитика.** Сценарии «что-если» (копия ответов и схемы весов; ⚠-бейдж при расхождении схем; применение восстанавливает веса); торнадо-чувствительность; Монте-Карло (seed, P10/P50/P90, вероятности категорий); снапшоты динамики I (фиксируют схему весов); карта портфеля «стоимость × I»; сводный акт по портфелю (с колонкой доказательной зрелости D).

**⚖️ Веса (AHP).** Активная схема весов и наборы организации (встроенные, пресеты, AHP, ручные с нормировкой к 100 %); редактор парных сравнений Саати 1–9 / 1/2–1/9; матрица 3×3; веса = главный собственный вектор; λmax, CI, **CR = CI/0,58** с вердиктом; применение при CR ≥ 0,1 — только через предупреждающее окно; при нестандартных весах везде показывается I при базовой схеме 30/35/35. Настройка — только роль «Аудитор».

**📄 Паспорт НИОКР.** Сведения; финансы (прогнозная стоимость и отклонение — автоматически); 7 контрольных условий; решение комиссии, обоснование, мероприятия.

**🗂 Портфель.** Матрица всех НИОКР, donut по категориям, средний балл, добавление/удаление, CSV. Все строки считаются по одной активной схеме весов.

**📚 Справочник.** База знаний с поиском: методика; TRL/УГТ и ГОСТ Р 15.301-2016; экономика (NPV/IRR/PP); мировые практики (Horizon Europe, Stage-Gate, AHP); якоря баллов 5/3/0 по 27 вопросам; галерея; источники.

**🖨 Акт оценки.** Итоговое заключение комиссии: результаты по блокам, строка схемы весов (с оговоркой при нестандартной), **пункт 5а «Доказательная база»** (число документов, D, K, нарушения по вопросам), контрольные условия, решение; печать/PDF и копирование в Word.

## 5. Роли и разделение ответственности

| Роль | Права |
| --- | --- |
| Аудитор | полные права: баллы, подтверждения, **веса**, контрольные условия, решения, портфель, реестр доказательств |
| Подразделение | паспорт, финансы, комментарии, **ведение реестра доказательств** (представляет документы); баллы и веса заблокированы |
| Наблюдатель | только чтение (в реестре доступны переходы к вопросам) |

Разделение реализует принцип методики: подразделение представляет доказательную картину, комиссия формирует независимую оценку и фиксирует схему весов.

## 6. Уведомления

- **Toast** — всплывающие сообщения справа сверху (оценки, нарушения правил, добавление/удаление документов, авто-подтверждения, применение весов);
- **Лента** — история сессии (кнопка 🔔 и блок на дашборде);
- **Push** — системные уведомления браузера после разрешения; без поддержки — автоматически toast-режим.

## 7. Математика (памятка)

```
Sⱼ = Σ баллов применимых вопросов блока j      (0…45)
Nⱼ = число применимых вопросов блока j          (0…9)
Pⱼ = Sⱼ / (5·Nⱼ)                                (0…1)
Bⱼ = Wⱼ · Pⱼ,   W = (30, 35, 35) — базовая схема; настраивается (AHP)
I  = 100 · Σ Bⱼ(прим.) / Σ Wⱼ(прим.)            (0…100)
```

«Н/П» исключает вопрос из числителя и знаменателя; блок целиком «Н/П» → ренормировка; все 27 «Н/П» → «Недостаточно данных». Шкала: 85–100 Высокая; 70–84 Хорошая; 50–69 Удовлетворительная; 30–49 Неудовлетворительная; 0–29 Критическая.

**Веса по AHP (Саати):** A·w = λmax·w (главный собственный вектор); CI = (λmax−3)/2; CR = CI/RI, RI(3) = 0,58; порог CR < 0,1. Пример: суждения 3/9/3 → веса ≈ 69,2/23,1/7,7 %, CR = 0.

**Доказательная зрелость (v6.0):**

```
D = 100 · (число оценённых вопросов с предоставленными документами) / (число оценённых вопросов)
K = 100 · (число вопросов с баллом 4–5, подтверждённых предоставленными документами) / (число вопросов с баллом 4–5)
```

Учитываются только документы со статусом «Предоставлен». K < 100 % означает прямые нарушения правила методики — они перечислены в акте (пункт 5а) и на карте нарушений.

## 10. Частые вопросы

- **Почему балл не ставится?** Проверьте роль (раздел 5) — баллы выставляет только «Аудитор».
- **Зачем кнопке 📎 красный ⚠?** Балл 4–5 по вопросу не подтверждён ни одним документом со статусом «Предоставлен» — это нарушение правила методики; добавьте документ или снизьте балл.
- **Документ есть, а подтверждение «Нет»?** Поставьте в реестре статус «Предоставлен» — подтверждение включится автоматически; либо в popup нарушения выберите «Отметить подтверждённым».
- **Что такое D и K?** D — доказательная зрелость всей оценки, K — соблюдение правила «4–5 только с документом». Для юридически устойчивого акта стремитесь к K = 100 %.
- **Как сравнить «до/после мероприятий»?** Вкладка «Аналитика»: два сценария — таблица покажет дельту I с учётом схем весов.
- **Насколько устойчив вывод?** Монте-Карло: P10 и P90 в разных категориях — решение чувствительно к погрешности оценок, нужно больше доказательств (следите за D).
- **Можно ли менять веса 30/35/35?** Да — решение комиссии, вкладка «⚖️ Веса (AHP)»; обосновывайте парными сравнениями с CR < 0,1, в акте появится оговорка и I при базовой схеме.
- **Печать не запускается?** Встроенный просмотрщик может блокировать window.print — используйте печать браузера.
